# Controller Refactor Plan

## Objective
Memecah controller besar menjadi unit yang lebih kecil dan mudah dirawat. Fokus pada pemisahan tanggung jawab, pengurangan logika bercampur, dan penyiapan lapisan bersama untuk reusability lintas fitur.

---

## Analysis by Controller

### 1. AuthController (8 methods, LOW COMPLEXITY)
**Responsibilities:**
- Show login form dengan role selection
- Handle login flow untuk 3 role: pengurus, kemahasiswaan, dan demo
- Session setup dan logout

**Extraction Candidates:**
- Pengurus account lookup & verification → `PengurusAuthenticator`
- User table lookup & verification → `UserAuthenticator`
- Demo account verification → `DemoAuthenticator`
- Session setup logic → `SessionManager`

**Target Split:**
- `AuthController` — thin: route, validate, delegate to service, set session, redirect
- `App\Services\Auth\PengurusAuthenticator` — query kemahasiswaan_ukm_accounts, verify password
- `App\Services\Auth\UserAuthenticator` — query users table, verify password
- `App\Services\Auth\DemoAuthenticator` — verify demo credentials dari config
- `App\Services\Auth\SessionManager` — session put/forget/migrate

### 2. MahasiswaController (43 methods, HIGH COMPLEXITY)
**Responsibilities:**
- Portal home & pages (beranda, tentang, organisasi, event, pengumuman, lost-found)
- Massive data aggregation via `data()` method (loads organizations, events, announcements, lost-found, notifications)
- Reference domain caching (loadReferenceDomain)
- Data transformation & mapping (untuk view structure tertentu)
- Lost-found form submission & image handling

**Extraction Candidates:**
- Data loading → `MahasiswaDataProvider`
- View transformation → `MahasiswaViewPresenter`
- Reference domain cache → `ReferenceValueService` (shared)
- Lost-found submission → `LostFoundSubmissionAction`
- Date/time formatting → `DateFormatterService` (shared)

**Target Split:**
- `HomeController` — beranda(), tentang()
- `OrganizationListController` — organisasiIndex(), organisasiShow(), organisasiDaftar()
- `EventController` — eventIndex(), eventShow(), organisasiEventShow()
- `AnnouncementController` — pengumumanIndex(), pengumumanShow()
- `LostFoundController` — lostFoundIndex(), reportLostFound()
- `App\Services\Mahasiswa\MahasiswaDataProvider` — load organizations, events, etc
- `App\Services\Mahasiswa\MahasiswaViewPresenter` — transform data untuk view structure

## Shared Services (Lintas Controller)

1. **ReferenceValueService**
   - Load workflow_reference_values dari DB
   - Cache per domain
   - Return label & payload
   - Used by: Mahasiswa, Kemahasiswaan, Pengurus

2. **StatusMappingService**
   - Map status code ke label & color
   - Status options per domain
   - Used by: Mahasiswa, Kemahasiswaan, Pengurus

3. **ContextResolverService**
   - Resolve organization_id dari session
   - Verify user authorization
   - Used by: Pengurus, Kemahasiswaan

4. **DateFormatterService**
   - Format date/time
   - Parse date strings
   - Used by: Mahasiswa, Pengurus

5. **MediaUploadService**
   - Handle file upload
   - Store to storage path
   - Generate public URL
   - Used by: Mahasiswa, Pengurus, Kemahasiswaan

6. **OrganizationProfileResolver**
   - Detect org type (BEM/UKM) dari name
   - Infer level (Universitas/Fakultas/Umum)
   - Infer category & field
   - Used by: Kemahasiswaan, potentially Pengurus

7. **SessionManager**
   - Put user data to session
   - Forget/invalidate session
   - Migrate token
   - Used by: Auth

## Implementation Order (Risk-Based)

### Phase 1: Shared Services (Foundation)
1. Extract `ReferenceValueService` (referenced by 3 controllers)
2. Extract `StatusMappingService` (repeated methods in multiple controllers)
3. Extract `ContextResolverService` (Pengurus + Kemahasiswaan)

### Phase 2: Auth (Low Risk, Small)
1. Create `SessionManager` service
2. Create `PengurusAuthenticator` service
3. Create `UserAuthenticator` service
4. Create `DemoAuthenticator` service
5. Refactor `AuthController` to be thin

### Phase 3: Mahasiswa (Medium Risk, Large)
1. Create `MahasiswaDataProvider`
2. Create `MahasiswaViewPresenter`
3. Split into 5 controllers
4. Keep route names same for backward compatibility

### Phase 4: Kemahasiswaan (Medium-High Risk, Large)
1. Create `OrganizationProfileResolver`
2. Create `OrganizationAccountSyncAction`
3. Split into 4 controllers
4. Keep route names same

### Phase 5: Pengurus (High Risk, Very Large)
1. Create `CalendarPdfParserService` (most complex, highest priority)
2. Create workflow services (Event, Proposal, Report)
3. Create data provider
4. Split into 6 controllers
5. Keep route names same

---

## Verification Checklist per Phase

- [ ] No syntax errors: run `php artisan tinker` and load class
- [ ] Routes still work: test via browser on key pages
- [ ] Session behavior unchanged: login/logout still work
- [ ] Data output same: spot-check view data structure
- [ ] No duplicate queries: monitor DB queries
- [ ] Tests pass: run `php artisan test` (if suite exists)

---

## Key Decisions

✓ Prioritize reusability: shared services first
✓ Keep route names unchanged: backward compatible
✓ Separate Query (Provider) from Command (Action/Workflow)
✓ Presenter pattern for view data transformation
✓ Service for domain logic (organization profile, auth)
✓ Extract complex parsing (PDF, calendar, profile detection) to own service
✓ No breaking changes to public API (routes, session keys)
